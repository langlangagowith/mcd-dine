# 麦门配餐 · 使用说明

> 一句话：**输入人数、人均预算、忌口，给你配一桌真的点得到的麦当劳 —— 每一份推荐都有出处，券后价算清。**
>
> 演示视频（25 秒，真实操作录屏）：[`docs/demo/mcd-dine-demo.mp4`](demo/mcd-dine-demo.mp4)

## 一、三种打开方式

### ① 只想看看界面（零配置，10 秒）

**双击 `index.html`**。

它内嵌了一份 2026-10-22 22:45 抓取的真实菜单快照（门店 1 家 / 菜单 82 项 / 门店券池 2 张），
所以**不联网、不起服务、不用 token** 就能改人数 / 预算 / 忌口，实时重排方案。
此时价格标「估算」—— 因为没走麦当劳侧的核价接口。

### ② 连真实 MCP（核价、券、建单都能用）

```bash
# 1) 放 token（只在本机，已被 .gitignore 忽略）
echo 'MCD_MCP_TOKEN=你的token' > .env.local

# 2) 起服务（会自动打开浏览器）
python run.py
# → http://127.0.0.1:8777
```

需要 Python 3.10+，**零第三方依赖**（纯标准库，MCP 走 Streamable HTTP 手写实现）。

### ③ 命令行 / 脚本调用

```bash
python run.py demo --people 3 --budget 40 --avoid beef,spicy --keyword 湖滨银泰
```

一次配餐 **12~16 次调用、5~7 秒**出结果。

## 二、界面怎么用

打开就是一张表单，所有输入都会立刻影响候选池，**点「配这一桌」才出方案**。

| 区域 | 说明 |
|---|---|
| **场景** | `到店自取` / `麦乐送`。选麦乐送时会要求填 beCode（门店编码），到店自取不传 |
| **人数** | `−` / `+` 步进，1~10 人 |
| **人均预算** | 滑块，20~80 元。**这是硬约束**：宁可少几块，绝不超一分 |
| **位置（到店用）** | 门店关键词，默认「湖滨银泰」。命中多家时取最近的在营门店 |
| **忌口（可多选）** | 不吃牛肉 / 鸡肉 / 猪肉 / 鱼虾 / 辣 / 蛋 / 乳制品 / 咖啡因。先按名称+标签过滤，组成不明的套餐再调 `query-meal-detail` 核实 |
| **偏好（可选）** | 想吃新品 / 低卡一点。只影响排序权重，不改变预算硬约束 |
| **配这一桌** | 触发枚举 + 核价 |

### 一次完整操作（也见演示视频）

1. 人数 `3 → 5`
2. 人均预算 `40 → 50` 元
3. 点「不吃辣」
4. 点「配这一桌」→ 约 5~7 秒（离线模式是瞬间）
5. 往下看方案卡：**最合预算 / 券省最多 / 其余候选**，每张卡都有逐项单价与理由
6. 到底部看**证据链**：门店券池、调用记录与 traceId

## 三、结果怎么读

每张方案卡从上到下是：

- **标签**：`最合预算` / `券省最多` …
- **方案结构**：`5 人 · 单点拼桌 · 高达吉士双牛堡、培根安格斯厚牛堡`
- **总价 / 人均 / 用掉预算百分比**（`用掉预算 100.0%` 就是刚好花完，不超一分）
- **逐项明细**：名称 × 份数 × 单价，以及它属于 `套餐` 还是 `主食/小食/饮料`
- **菜单现价**：每个单品的 `菜单现价 鸡腿堡单品精选 ×1，23.50 元/份`
- **本地合计**：把预算算式写出来，方便当场核对
- **券池**：这桌能不能用券；能用时给「券前 → 券后」
- **过滤记录**：`已按忌口排除 9 个候选，本方案 0 冲突`
- **建单**：连真实 MCP 时才可点，且下单前会再核一次价，金额与页面不一致就拒绝

**证据链**区块：门店券池（券 ID / 券码 / 适用商品）+ 调用记录。
每条记录带 `traceId`，可在麦当劳侧追溯 —— 这是本项目和其他"按经验配"的工具最大的区别。

## 四、边界与已知限制（都是实测出来的，不是免责声明）

1. **门店打烊就直接报错** `600057 门店可能已关闭或不在营业时间`。
   所以演示/验证要么在营业时段，要么选 24 小时店（如杭州朝晖 `3330016`，00:00-23:59）。
   产品层不会白屏，会告诉你营业时间并列出附近还在营业的店。
2. **券对「整行」生效**：一行 3 份 22.5 元挂 11.9 元券，接口返回 11.90 —— 它把整行当 1 份。
   本项目把券行拆成「1 份带券 + 其余原价」再核，实测 56.90 元才是真实金额。
3. **套餐不报热量**：`list-nutrition-foods` 只有单品，给套餐套单品热量会严重低估。
   覆盖率不足 3/4 就整桌不报 —— 宁可不说，也不给假精确。
4. **不自动付款、不代点**：建单是给你省输入，付款留给你。
5. **券价/满减随活动变化**，`docs/evidence/` 里的记录都带时间戳与 traceId，可复核当时状态。

## 五、常见问题

**Q：为什么价格旁边写「估算」？**
因为没走核价接口（离线快照模式）。连上真实 MCP 后就是逐方案 `calculate-price` 的真实金额。

**Q：没有 token 能玩吗？**
能。`index.html` 双击即用，只是数字是估算、不能建单。

**Q：为什么候选 2000 多个却只核价 6 个？**
MCP 限流 600 次/分钟、单次 300~500ms。把 35 个工具丢给模型挨个试错既慢又贵。
这里改成「本地枚举 + 少量核价」：本地筛出 Top-6，只对这 6 个调真价接口。

**Q：数据从哪来？**
麦当劳中国 MCP（`mcp.mcd.cn`）：`query-nearby-stores` / `query-meals` / `query-meal-detail` /
`query-store-coupons` / `calculate-price` / `list-nutrition-foods` / `create-order`。
真实调用记录见 `docs/evidence/2026-10-22-live-calls.md`。
